## 1. 단일 블루 브랜드 아이덴티티 및 상태 컬러 엄격 제한 (Brand Blue & Semantic Discipline)

화려한 형광색이나 제각각인 컬러 팔레트를 전면 금지하고, 신뢰할 수 있는 엔터프라이즈 모노톤 위에 블루 단일 브랜드 컬러와 의미론적 상태 컬러만 정밀하게 사용합니다:

### 1.1 브랜드 블루 계층 (Unified Brand Blue)
- **Primary Brand**: `#2563eb` (Blue 600) — 핵심 액션, 포커스 링, 활성 탭 인디케이터
- **Deep / Hover**: `#1d4ed8` (Blue 700), `#1e40af` (Blue 800) — 마우스 호버 및 프라이머리 버튼
- **Surface Tint**: `#eff6ff` (Blue 50) — 선택된 행, 가벼운 배경 틴트
- **Subtle Border**: `#bfdbfe` (Blue 200) — 브랜드 강조 시 극도로 옅은 경계

### 1.2 기능적 시맨틱 컬러 한정 사용 (Functional Semantic Colors ONLY)
- **정상 가동 (Normal)**: `#059669` (Emerald 600), 배경 `#ecfdf5`
- **주의 / SLA 지연 (Warning)**: `#d97706` (Amber 600), 배경 `#fffbeb`
- **경고 / 파이프라인 실패 (Critical / Danger)**: `#dc2626` (Red 600), 배경 `#fef2f2`
- **시맨틱 예외 금지**: 녹색/주황/빨간색은 오직 장치나 데이터의 '물리적/논리적 상태'를 전달할 때만 점(Dot) 또는 1px 테두리로 절제하여 사용합니다. 메뉴 아이템이나 카드를 알록달록한 배경 박스로 도배하는 행위를 엄격히 금지합니다.

## 2. 안티 벤또 & 탈박스 규율 (Anti-Box & Anti-Bento Disciplined Architecture)

> **"박스 안에 박스를 넣지 말고, 배경색·테두리·그림자를 동시에 쓰지 마라. 경계 구분은 넉넉한 여백과 옅은 직선으로 하라."**

### 2.1 3대 절대 금기 (Strict Prohibitions)
1. **박스 안에 박스 중첩 금지 (No Nested Boxes)**:
   - 컨테이너 카드 안에 또다시 둥근 박스를 겹겹이 쌓아 화면을 잘게 조각내는 프랙탈/벤또 디자인을 배제합니다.
2. **배경색 + 테두리 + 그림자 삼중 사용 금지 (No Simultaneous Bg + Border + Shadow)**:
   - 배경색을 넣은 영역은 테두리를 제거합니다.
   - 테두리를 넣은 영역은 배경을 투명하게 유지합니다.
   - 그림자(`box-shadow`)는 고정된 카드에 남발하지 않고, 오직 **마우스 롤오버(Hover)**나 **플로팅(Dropdown / Modal)** 인터랙션에만 한정합니다.
3. **AI 전형의 라운드 박스 좌측 굵은 테두리 금지 (No Left Thick Borders)**:
   - 라운드 박스 좌측에 4px~6px 굵은 컬러 선을 넣는 AI 전형의 콜아웃 스타일은 저품질 디자인으로 규정하여 엄격히 금지합니다.

### 2.2 여백 기반 공간 구획 (Whitespace Rhythm)
- 요소 간의 경계는 박스가 아닌 **네거티브 스페이스(Whitespace)**로 구분합니다:
  - 거시 섹션 간격: `margin-bottom: 38px ~ 48px`
  - 마크로 메트릭 및 열 간격: `gap: 32px ~ 48px`
- 구분선이 불가피할 경우, 곡선 없이 **직선의 극도로 옅은 헤어라인 (`1px solid #f1f5f9`)**을 사용하여 구분선 자체가 시각적 노이즈를 유발하지 않도록 합니다.

### 2.3 가로 단수 균등 분할 규칙 (Equal Split Harmony)
- 비산적이고 산발적인 비정형 분할을 지양하고, `1:1`, `1:1:1`, `1:1:1:1` 또는 `2:1` 비율의 균등분할 그리드를 사용하여 화면 전체에 탄탄한 질서와 구조적 안정감을 부여합니다.

### 2.4 UI 컴포넌트 형태 차별화 (Anti-Capsule Cliché)
- 모든 박스, 뱃지, 입력창이 전부 캡슐(알약) 형태로 획일화되는 안티패턴을 배제합니다:
  - **버튼**: 섬세한 4px 반경 + 명확한 기능 텍스트.
  - **탭**: 보더리스 텍스트 + 활성 시 단정한 2px 하단 직선 인디케이터.
  - **상태 뱃지/라벨**: 둥근 캡슐 대신 6px 솔리드 점(Dot) 또는 고정폭 모노스페이스 플랫 라벨.

## 3. 극단적 미사여구 배제 & 단순 명사화 원칙 (Zero Fluff & Pure Data Discipline)

- **설명글 및 홍보성 수식어 전면 제거**:
  - '통합 거버넌스 오버뷰', '15대 독립 서비스. 84대 무인장치 실시간 모니터링 KST' 같은 장황한 설명글을 전면 삭제합니다.
  - 메인 화면 타이틀은 오직 **`오버뷰`**처럼 단일 명사로 표기합니다.
- **순수 데이터 중심의 서브 타이틀**:
  - 부가적인 텍스트 서술을 배제하고, 정확한 타임스탬프(`2026.11.20 (금) 13:58:49 KST`)만을 모노스페이스로 깔끔하게 노출합니다.
  - 화면상 꼭 필요한 부가 정보는 텍스트를 늘어놓지 말고 **`ⓘ` 툴팁** 형태로 분리합니다.
- **탭/메뉴 명칭 단일 단어 축약**:
  - '전체 종합 매트릭스' ➔ **`전체`**, '뉴스보드' ➔ **`뉴스`**, '캠핑' ➔ **`캠핑`** 등 1단어로 축약합니다.
- **메뉴 간격 확보 및 텍스트 겹침 방지**:
  - 탭 간격을 최소 `gap: 24px ~ 32px` 이상 부여하고 `white-space: nowrap`, `flex-shrink: 0`을 지정하여 텍스트 겹침이나 어색한 2줄 줄바꿈을 원천 차단합니다.

## 4. 모바일 320px 무오버플로우 절대 규칙 (320px Zero-Overflow Absolute Law)

> [!IMPORTANT]
> **LDS 모바일 절대 원칙**:  
> iPhone SE 기준 가로폭 **320px에서 어떤 컨텐츠나 UI도 브라우저 밖으로 1px조차 벗어나지 않아야 합니다.**  
> 항상 `scrollWidth === clientWidth === 320px` (`DIFF: 0`)을 만족해야 합니다.

1. **상단 서비스명 고정 노출 배제**:
   - 모바일에서 상단 중앙에 서비스명을 무조건 고정 노출하지 않습니다. 작은 화면에서는 각 메뉴별로 필요한 컨텐츠와 핵심 UI만 정확하고 심플하게 제공합니다.
2. **명확한 모바일 섹션 위계**:
   - 모바일에서는 섹션 간 구분이 흐려지지 않도록 세로 간격을 넓히거나(`32px ~ 40px`), 섹션 타이틀을 크고 굵게(`font-size: 16px ~ 17px`, `font-weight: 800`) 적용하여 명확한 시각적 구분을 제공합니다.
3. **데스크톱 다단 테이블의 스택 자동 전환**:
   - 데스크톱의 다단 `<table>`은 모바일(`max-width: 900px`) 진입 시 `display: block` 기반의 버티컬 스택 카드로 100% 전환합니다.
4. **텍스트 줄바꿈 및 오버플로우 방지 전역 적용**:
   - 모든 제목, 문단, 테이블 셀, 모노스페이스 해시에 `word-break: break-word`, `overflow-wrap: anywhere`, `box-sizing: border-box`를 전역 적용합니다.
   - SHA-256 해시값(64자) 등 긴 문자열은 반드시 `word-break: break-all`로 강제 개행합니다.

### 4.1 운영 화면 텍스트·아이콘 규칙 (LDS v3.6)

- 일반 텍스트는 전역 `word-break: keep-all`을 사용한다. 폭이 부족하면 단어를 쪼개지 말고 데이터 항목을 세로로 적층한다.
- 화면의 설명문은 최소화한다. 필요한 근거·계산식·정의는 `i` SVG 아이콘의 툴팁으로 제공한다.
- 메뉴와 카테고리는 가로폭 전체를 균등 분할한 언더라인 탭으로 표현한다. 좁은 화면에서는 같은 규칙으로 행을 추가한다.
- 접기·펼치기 같은 텍스트 제어는 쓰지 않는다. Tabler 또는 Lucide 계열의 인라인 SVG 화살표만 쓴다. 기본은 라인 아이콘, 활성 상태는 채움 아이콘을 쓴다.
- 반복되는 라벨·같은 의미의 상태 문구를 한 화면에 중복하지 않는다. 액션은 짧은 명사로 쓴다.

## 5. 정보 단절 없는 심층 탐색 구조 (Continuous Deep Drilldown Engine)

운영 관제 및 서비스 데이터는 단순히 수치를 보여주고 끝나는 것이 아니라, 상위 관제에서 최하위 원천 로그까지 끊김 없이 유기적으로 파고들 수 있어야 합니다:

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│  [1단계: 거시 오버뷰] 84대 무인장치 상태 요약 & 5대 주의/지연 알림 스트립          │
└────────────────────────────────────────┬─────────────────────────────────────────┘
                                         ▼ (인라인 확장 클릭)
┌──────────────────────────────────────────────────────────────────────────────────┐
│  [2단계: 서비스 인라인 콕핏] 실시간 리소스(CPU/RAM) & 4단계 파이프라인 (수집-분석-검증-운영)│
└────────────────────────────────────────┬─────────────────────────────────────────┘
                                         ▼ (상세 탭 전환)
┌──────────────────────────────────────────────────────────────────────────────────┐
│  [3단계: 실측 검증 게이트] SHA-256 데이터 해시 & 산출물 건수 & Commit ID           │
└────────────────────────────────────────┬─────────────────────────────────────────┘
                                         ▼ (원천 데이터 탐색)
┌──────────────────────────────────────────────────────────────────────────────────┐
│  [4단계: Raw Data JSON 익스플로러] 원본 JSON 및 이벤트 레코드 실시간 검증          │
└──────────────────────────────────────────────────────────────────────────────────┘
```

1. **프로세스 성공과 데이터 품질 통과 분리**:
   - GitHub Actions / 워크플로우 실행 성공(Exit Code 0)과 산출물 데이터 품질 검증(Quality Gate)을 분리하여 상태를 기록합니다.
2. **원천 증거(Provenance) 추적**:
   - 정적 스냅샷(`configured_snapshot`)과 실제 수집 실행 이벤트(`observed_runs`)를 명확히 구분하여 가짜 누적 지표 표기를 원천 차단합니다.
3. **인라인 콕핏 시트 (Cockpit Sheet)**:
   - 별도 페이지 이동으로 인한 컨텍스트 단절 없이, 테이블 행 바로 아래에서 인라인으로 4단계 파이프라인과 원천 해시를 검증할 수 있는 확장 구조를 제공합니다.

## 6. 차트 컨트롤 및 시간 표기 표준 (Chart Controls & Temporal Standards)

1. **차트 기간 필터 (Segmented Control)**:
   - 모든 시계열 차트는 `일 (Day)`, `월 (Month)`, `년 (Year)` 필터를 지원하여 원하는 단위로 수집량과 처리량을 분석할 수 있어야 합니다.
2. **시간 표기 표준**:
   - 기본 표기: `12분 전`, `3시간 전` 등 상대 시간.
   - 호버 / 상세 표기: `YYYY.MM.DD (요일) HH:MM:SS KST` 정밀 타임스탬프.
